01 — Network

🔢 Quản lý địa chỉ IP

Chiến lược quy hoạch IP là nền tảng của mọi hệ thống. Làm sai từ đầu → đau khi scale.

📐 CIDR Planning — Phân vùng subnet

🏭 Production VPC
10.0.0.0/16
Public: 10.0.1.0/24
Private: 10.0.10.0/24
DB: 10.0.20.0/24
🧪 Staging VPC
10.1.0.0/16
Public: 10.1.1.0/24
Private: 10.1.10.0/24
DB: 10.1.20.0/24
💻 Dev VPC
10.2.0.0/16
Public: 10.2.1.0/24
Private: 10.2.10.0/24
DB: 10.2.20.0/24
💡 Rule của thumb
Dùng /16 cho mỗi environment (65k IPs). Chia subnet /24 theo tier: public (ALB/NAT), private (app pods), database. Tránh overlap giữa các VPC nếu sau này cần VPC Peering.

🔒 Security Group / Firewall Rules

🛡️ security-group-rules.tf (Terraform)
# ALB Security Group — chỉ accept 80/443 từ internet
resource "aws_security_group" "alb_sg" {
  name   = "prod-alb-sg"
  vpc_id = aws_vpc.main.id

  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# App Security Group — chỉ accept từ ALB
resource "aws_security_group" "app_sg" {
  ingress {
    from_port       = 8080
    to_port         = 8080
    protocol        = "tcp"
    security_groups = [aws_security_group.alb_sg.id]
  }
}

# DB Security Group — chỉ accept từ App tier
resource "aws_security_group" "db_sg" {
  ingress {
    from_port       = 5432
    to_port         = 5432
    protocol        = "tcp"
    security_groups = [aws_security_group.app_sg.id]
  }
}
⚠️ AWS EKS — IP Exhaustion
EKS CNI mặc định cấp 1 IP/pod từ subnet. Với node m5.large tối đa 10 pods. Khi subnet chỉ còn vài IP free → pod pending. Fix: dùng prefix delegation hoặc tăng subnet size sớm.

resource "aws_acm_certificate" "wildcard" {

✅ Best Practice
Dùng wildcard cert *.company.com thay vì cấp cert riêng từng service. 1 cert cover toàn bộ subdomains. Kết hợp với cert-manager trên K8s để auto-renew.

04 — Container

🐳 Docker Setup Hiệu Quả

Dockerfile chuẩn cho Spring Boot service — multi-stage build, non-root user, health check đầy đủ.

📦 Multi-Stage Dockerfile — Spring Boot

🐳 Dockerfile
# Stage 1: Build
FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /app
# Copy pom.xml trước để cache layer dependency
COPY pom.xml .
RUN mvn dependency:go-offline -q
COPY src ./src
RUN mvn package -DskipTests -q

# Stage 2: Runtime
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app

# Non-root user — security best practice
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# Copy jar từ builder stage
COPY --from=builder /app/target/*.jar app.jar

# JVM options cho container (Java 21 auto-detect container CPU/memory)
ENV JAVA_OPTS="-XX:+UseContainerSupport \
  -XX:MaxRAMPercentage=75.0 \
  -Djava.security.egd=file:/dev/./urandom"

# Health check
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD wget -qO- http://localhost:8080/actuator/health || exit 1

EXPOSE 8080
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
⚡
Layer Cache Optimization
Copy pom.xml trước, chạy dependency:go-offline, rồi mới copy source. Khi chỉ đổi code, layer deps được cache lại → build nhanh hơn 5-10x.
📉
Image Size
Alpine JRE image chỉ ~200MB so với JDK ~600MB. Multi-stage loại bỏ Maven, source code, build artifacts khỏi image production.
🔒
Non-Root Security
Container chạy với user appuser thay vì root. Nếu container bị compromise, attacker không có root access vào host.
🧠
Memory Config
MaxRAMPercentage=75 giúp JVM tự điều chỉnh heap theo container limit, thay vì dùng toàn bộ RAM host.

06 — Proxy

⚡ Nginx Reverse Proxy

Nginx làm API Gateway local — route traffic theo path hoặc subdomain đến đúng service.

🔀 Path-based routing

⚡ nginx/conf.d/default.conf
upstream rider_backend {
    server rider-service:8080;
    keepalive 32;
}

upstream term_life_backend {
    server term-life-service:8080;
    keepalive 32;
}

server {
    listen 80;
    server_name api.local;

    # Global timeout
    proxy_connect_timeout 10s;
    proxy_read_timeout    60s;
    proxy_send_timeout    60s;

    # Pass real IP
    proxy_set_header X-Real-IP        $remote_addr;
    proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Host             $host;

    # Route /api/rider/* → rider-service
    location /api/rider/ {
        proxy_pass http://rider_backend;
        rewrite ^/api/rider/(.*) /api/$1 break;
    }

    # Route /api/term-life/* → term-life-service
    location /api/term-life/ {
        proxy_pass http://term_life_backend;
        rewrite ^/api/term-life/(.*) /api/$1 break;
    }

    # Health check endpoint
    location /health {
        access_log off;
        return 200 "OK\n";
    }
}

🔐 HTTPS với self-signed cert (local)

🔑 Generate self-signed cert
# Generate cert cho *.local
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout certs/local.key \
  -out certs/local.crt \
  -subj "/CN=*.local/O=Dev" \
  -addext "subjectAltName=DNS:*.local,DNS:localhost"

# Trust cert trên macOS
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain certs/local.crt

variables:
  DOCKER_DRIVER: overlay2
  IMAGE_NAME: $CI_REGISTRY_IMAGE
  IMAGE_TAG: $CI_COMMIT_SHA
  MAVEN_OPTS: "-Dmaven.repo.local=$CI_PROJECT_DIR/.m2"

# Cache Maven dependencies giữa các job
cache:
  key: "${CI_PROJECT_PATH}-maven"
  paths: [.m2/]

stages:
  - validate
  - test
  - build
  - deploy

# ── VALIDATE ─────────────────────────────────
checkstyle:
  stage: validate
  image: maven:3.9-eclipse-temurin-21
  script:
    - mvn checkstyle:check -q
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"

# ── TEST ─────────────────────────────────────
unit-test:
  stage: test
  image: maven:3.9-eclipse-temurin-21
  services:
    - name: postgres:16-alpine
      alias: postgres
      variables:
        POSTGRES_DB: test_db
        POSTGRES_USER: test
        POSTGRES_PASSWORD: test
  variables:
    SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/test_db
    SPRING_DATASOURCE_USERNAME: test
    SPRING_DATASOURCE_PASSWORD: test
  script:
    - mvn test -pl rider-service
  artifacts:
    reports:
      junit: rider-service/target/surefire-reports/*.xml
    paths: [rider-service/target/surefire-reports/]
    expire_in: 7 days

# ── BUILD & PUSH IMAGE ────────────────────────
build-image:
  stage: build
  image: docker:24
  services: [docker:24-dind]
  before_script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
  script:
    - |
      docker build \
        --cache-from $IMAGE_NAME:latest \
        --build-arg BUILDKIT_INLINE_CACHE=1 \
        -t $IMAGE_NAME:$IMAGE_TAG \
        -t $IMAGE_NAME:latest \
        -f rider-service/Dockerfile \
        rider-service/
    - docker push $IMAGE_NAME:$IMAGE_TAG
    - docker push $IMAGE_NAME:latest
  rules:
    - if: $CI_COMMIT_BRANCH == "main" || $CI_COMMIT_BRANCH == "develop"

# ── DEPLOY STAGING ───────────────────────────
deploy-staging:
  stage: deploy
  image: bitnami/kubectl:latest
  environment:
    name: staging
    url: https://api.staging.company.com
  before_script:
    - kubectl config set-cluster eks --server=$K8S_SERVER --insecure-skip-tls-verify=true
    - kubectl config set-credentials deployer --token=$K8S_TOKEN
    - kubectl config set-context default --cluster=eks --user=deployer --namespace=staging
    - kubectl config use-context default
  script:
    - kubectl set image deployment/rider-service rider=$IMAGE_NAME:$IMAGE_TAG
    - kubectl rollout status deployment/rider-service --timeout=5m
  rules:
    - if: $CI_COMMIT_BRANCH == "develop"

# ── DEPLOY PRODUCTION ────────────────────────
deploy-production:
  stage: deploy
  extends: .deploy-staging  # kế thừa config
  environment:
    name: production
    url: https://api.company.com
  variables:
    NAMESPACE: production
  when: manual   # bắt buộc manual trigger cho prod
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
✅ Best Practices CI/CD
1. Dùng when: manual cho production deploy — tránh deploy tự động lên prod.
2. --cache-from giảm build time Docker bằng cách tận dụng layer cache từ image cũ.
3. kubectl rollout status --timeout=5m để pipeline fail nếu deployment không healthy trong 5 phút.
08 — Runner

🏃 GitLab Runner Setup

Cài GitLab Runner trên máy riêng hoặc trong Kubernetes — mỗi cách có trade-off khác nhau.

🐳
Docker Executor
Mỗi job chạy trong container riêng. Isolation tốt. Cần Docker-in-Docker cho build image. Setup đơn giản nhất.
☸️
Kubernetes Executor
Runner tạo pod mới cho mỗi job. Auto-scale, không lo thiếu resource. Setup phức tạp hơn nhưng phù hợp production.

concurrent = 4  # số job chạy song song
check_interval = 3

[[runners]]
  name = "docker-runner-01"
  url = "https://gitlab.company.com"
  token = "xxx"
  executor = "docker"
  [runners.custom_build_dir]

  [runners.cache]
    Type = "s3"          # Cache lên S3 — share giữa runners
    Shared = true
    [runners.cache.s3]
      ServerAddress = "s3.amazonaws.com"
      BucketName = "company-gitlab-cache"
      BucketLocation = "ap-southeast-1"

  [runners.docker]
    image = "alpine:latest"
    privileged = false         # KHÔNG dùng privileged trừ khi cần DinD
    disable_cache = false
    volumes = ["/cache", "/var/run/docker.sock:/var/run/docker.sock"]
    shm_size = 268435456      # 256MB SHM cho postgres service
    pull_policy = ["if-not-present"]  # tránh pull image mỗi lần
⚠️ Lưu ý quan trọng
Đừng đặt privileged = true trừ khi thực sự cần Docker-in-Docker. Thay vào đó, mount /var/run/docker.sock để dùng Docker daemon của host — an toàn hơn.
09 — Kubernetes

☸️ EKS Deployment Setup

Cấu hình K8s đầy đủ cho microservice — Deployment, Service, Ingress, ConfigMap, HPA.

☸️ k8s/rider-service/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: rider-service
  namespace: production
  labels:
    app: rider-service
    version: "$IMAGE_TAG"  # replaced by CI/CD
spec:
  replicas: 2
  selector:
    matchLabels:
      app: rider-service
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0   # zero downtime
      maxSurge: 1
  template:
    metadata:
      labels:
        app: rider-service
    spec:
      # Spread pods across AZs
      topologySpreadConstraints:
        - maxSkew: 1
          topologyKey: topology.kubernetes.io/zone
          whenUnsatisfiable: DoNotSchedule
          labelSelector:
            matchLabels:
              app: rider-service
      containers:
        - name: rider
          image: registry.gitlab.com/company/rider-service:latest
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: rider-config
            - secretRef:
                name: rider-secrets
          resources:
            requests:
              cpu: 250m
              memory: 512Mi
            limits:
              cpu: 500m
              memory: 1Gi
          readinessProbe:
            httpGet:
              path: /actuator/health/readiness
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /actuator/health/liveness
              port: 8080
            initialDelaySeconds: 60
            periodSeconds: 30
---
apiVersion: v1

🔑
Dùng Partition Key đúng
Key = policyNumber hoặc customerId → tất cả event của 1 policy luôn vào cùng partition → đảm bảo ordering per-policy.
📊
Số Partition
Partition = max consumer instances dự kiến. Bắt đầu với 6-12 partition. Tăng dễ, giảm không được — tính toán kỹ từ đầu.
⏱️
Retention Policy
Business event: retention.ms=7d. Audit log: 30d. Temp/notification: 1d.
🔁
Replication Factor
Production: RF=3 (min.insync.replicas=2). Dev/staging: RF=1 để tiết kiệm.

🛡️ Dead Letter Topic Pattern

☕ KafkaConsumerConfig.java
@Bean
public DefaultErrorHandler errorHandler(KafkaTemplate<String, Object> template) {
    // Gửi message lỗi sang DLT sau 3 lần retry
    DeadLetterPublishingRecoverer recoverer =
        new DeadLetterPublishingRecoverer(template,
            (record, ex) -> new TopicPartition(
                record.topic() + ".DLT", record.partition()));

    // Exponential backoff: 1s → 2s → 4s
    ExponentialBackOffWithMaxRetries backoff =
        new ExponentialBackOffWithMaxRetries(3);
    backoff.setInitialInterval(1000L);
    backoff.setMultiplier(2.0);

    DefaultErrorHandler handler = new DefaultErrorHandler(recoverer, backoff);
    // Không retry deserialization error
    handler.addNotRetryableExceptions(DeserializationException.class);
    return handler;
}
⚠️ Consumer Group Naming
Mỗi service dùng 1 consumer group riêng. Không share consumer group giữa các service khác nhau. Nếu 2 instance của cùng service → cùng group → Kafka tự load balance partition giữa chúng.

@Configuration
@EnableWebSecurity
public class SecurityConfig {

  @Bean
  public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    return http
      .csrf(AbstractHttpConfigurer::disable)
      .sessionManagement(s -> s
        .sessionCreationPolicy(SessionCreationPolicy.STATELESS))
      .authorizeHttpRequests(auth -> auth
        .requestMatchers("/actuator/health/**").permitAll()
        .requestMatchers(HttpMethod.GET, "/api/public/**").permitAll()
        .requestMatchers("/api/admin/**").hasRole("ADMIN")
        .anyRequest().authenticated())
      .oauth2ResourceServer(oauth2 -> oauth2
        .jwt(jwt -> jwt.jwtAuthenticationConverter(jwtConverter())))
      .build();
  }

  @Bean
  public JwtAuthenticationConverter jwtConverter() {
    JwtGrantedAuthoritiesConverter grantedConverter = new JwtGrantedAuthoritiesConverter();
    grantedConverter.setAuthoritiesClaimName("roles"); // custom claim
    grantedConverter.setAuthorityPrefix("ROLE_");
    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(grantedConverter);
    return converter;
  }
}

@Service
public class EbaoService {

  // Thứ tự: TimeLimiter → CircuitBreaker → Retry → Bulkhead
  @TimeLimiter(name = "ebao-client")
  @CircuitBreaker(name = "ebao-client", fallbackMethod = "submitFallback")
  @Retry(name = "ebao-client")
  public CompletableFuture<EbaoResponse> submitRider(RiderRequest request) {
    return CompletableFuture.supplyAsync(
      () -> ebaoFeignClient.submit(request));
  }

  // Fallback khi Circuit Breaker OPEN
  public CompletableFuture<EbaoResponse> submitFallback(
      RiderRequest req, Throwable ex) {
    log.warn("eBao circuit open, queuing for retry: {}", ex.getMessage());
    // Lưu vào outbox table để retry sau
    outboxService.save(req);
    return CompletableFuture.completedFuture(EbaoResponse.queued());
  }
}

📊 Circuit Breaker States

CLOSED
bình thường
→ 50% fail →
OPEN
fail fast
→ sau 30s →
HALF-OPEN
thử 5 req
HALF-OPEN: success → CLOSED  |  fail → OPEN lại
🏊
Bulkhead Pattern
Giới hạn số concurrent calls đến một service. Nếu eBao chậm, chỉ tối đa N thread bị block — service còn lại vẫn healthy.
📮
Outbox Pattern
Khi Circuit OPEN, lưu request vào outbox table. Scheduler chạy lại khi service recover. Không mất data.
🩺
Health Indicator
Expose circuit breaker state qua /actuator/health. K8s có thể dùng để drain pod khi nhiều CBs đang OPEN.
⏳
Timeout Hierarchy
Feign timeout < Resilience4j TimeLimiter < Nginx proxy timeout. Nếu ngược lại → timeout ở tầng ngoài trước, tầng trong không có cơ hội retry.
